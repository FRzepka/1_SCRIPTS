# Review 1: local supplementary analyses

This folder contains analyses reproduced from existing predictions, exported model
headers, saved STM32 benchmark summaries, and a local PC re-execution of the three
exported SOH C models. No model was trained and no STM32 firmware was executed for
these results.

## Snapshot protection

- `review_1` is a working copy of the previous manuscript directory.
- The 60 source files were compared with their copies using SHA-256.
- Missing files: 0. Hash differences: 0.
- All new work is located below `review_1`; the original manuscript files outside
  this directory were not edited.

## Generated analyses

- `results/long_horizon`: MAE, RMSE, bias, P95, cumulative MAE, and deviation from
  the Base model over ten consecutive segments of the complete streaming outputs.
  The SOC analysis covers 14,499,039 samples and SOH covers 14,496,990 samples.
- `results/filter`: direct comparison of raw SOH predictions, the filter used by
  the saved benchmark code, and the different filter stated in the manuscript.
  Base, Pruned, and Quantized were all re-executed locally on the same complete C07
  sequence so the raw-to-filter comparison is internally consistent.
- `results/utility`: all 1,771 combinations of four non-negative utility weights
  on a 5% grid plus focused priority sweeps.
- `results/weights`: recurrent-weight distributions, L2 unit saliency, INT8
  reconstruction error, and explicit storage/state accounting.
- `results/operations`: static multiply-accumulate counts and the extra per-weight
  scale multiplications in the current quantized C kernels.
- `results/faults`: held-output simulations for missing estimator updates and a
  limited software experiment that flips one bit in the floating-point output.
- `../figures/Review_1_Additional`: 39 PNG figures generated from these tables.

The original benchmark did not save the raw Quantized SOH trajectory. It has now
been newly generated by executing the exported Quantized C model locally. Base and
Pruned were re-executed in the same Windows environment to avoid comparing this new
trajectory against archived Linux outputs. The local run and its limitations are
documented in `LOCAL_WINDOWS_REEXECUTION.md`.

## Reproduction


Use `-SkipSequenceAnalyses` to regenerate figures and header-based analyses without
re-reading the large NPZ trajectories.

## Interpretation limits

- The long-horizon results reuse saved streaming predictions. They test temporal
  stability of those completed runs, not a newly executed model.
- The local raw-to-filter comparison is a separate Windows C re-execution. Its
  values must not be silently combined with the archived Linux benchmark values.
- The utility analysis uses the existing energy numbers. Those numbers were
  calculated as inference time times an assumed constant board power of 0.5 W.
- The filter time constants assume the documented 1 Hz sampling rate.
- The bit-flip experiment affects only the stored floating-point estimator output.
  It is not an internal-weight, activation, recurrent-state, sensor, or MCU fault
  campaign and must not be described as one.
- Weight distributions can document how the trained models differ, but they do not
  prove that pruning caused regularization or that the result persists across seeds.
